# 仕様書

## 1. 目的

さいたま市の家庭ごみの収集日・分別区分を確認するアプリ。市の公式情報と同じ内容を扱うが、
**トップページを開いた瞬間に「明日は何ごみか」が分かる**ことだけを目的に画面を組み直す。

ごみ出しは前夜〜当日朝に思い出す行動であるため、「今日」ではなく「明日」を主役に据える。

## 2. 対象ユーザー・利用環境

- さいたま市内の家庭ごみ収集地区に住み、日常的にごみを出す人
- iPhone（iOS 16以降を想定）。Flutter実装のため将来Androidにも展開できる
- 通信環境を問わない。収集ルールの判定・設定の保存はすべて端末内で完結し、外部通信は行わない

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| 区分 | もえるごみ・もえないごみ・有害危険ごみ・資源物1類・資源物2類の5種類 |
| 地区 | 収集曜日の組み合わせの単位。区（10区）の下に位置する。ユーザーは地区名ではなく「自分の収集曜日」を登録する |
| 収集ルール | ある区分が「何曜日」「月内の第何週」に収集されるかを表す最小単位 |
| 早朝収集地区 | もえるごみを朝5:30までに出す必要がある地区（大宮区・浦和区の一部） |

## 4. 機能要件

### 4.1 初回設定（オンボーディング）

- アプリ起動時、地区が未設定なら他の画面に進めず初回設定を表示する
- お住まいの区（10区から選択）を選ぶ
- 区分ごとに収集曜日を設定する。曜日は複数選択可（もえるごみは週2回あるなど）
- 曜日を選んだ区分には頻度（毎週／第1・第3／第2・第4／第1のみ〜第4のみ）を指定できる。
  デフォルトは「毎週」
- 曜日の入力を助ける雛形（プリセット）をワンタップで適用できる。プリセットは「もえるごみが
  月・木の地区」のように、もえるごみの曜日だけが決まっているひな形で、他の区分は個別入力する
- もえるごみの早朝収集地区かどうかをスイッチで設定できる
- 地区に任意の名前を付けられる（未入力なら「わたしの地区」）
- 1区分以上に曜日が設定されていなければ「この設定ではじめる」は押せない
- 保存すると本体（ホーム・カレンダー・設定の3タブ）に遷移する

### 4.2 ホーム

- 明日の収集区分を画面内で最も大きく表示する（アイコン・区分名・色）
  - 区分がなければ「収集はありません」、1/1〜1/3の年末年始休止期間中は「年末年始のお休み」
  - 区分がある場合は出す期限（通常8:30、早朝収集地区のもえるごみのみ5:30）と、
    先頭区分の出し方の要点を添える
  - タップすると日別詳細シートを開く
- 今日の収集区分を明日より小さく1行で表示する（タップで日別詳細）
- あさって以降、直近6件の「収集がある日」を一覧表示する（区分ごとにバッジ表示、タップで詳細）
- 区分ごとの次回収集日を独立したセクションとして一覧表示する。月1回しかない区分
  （もえないごみ等）は日付一覧を眺めても見つけにくいため
- 地区に一件も曜日が設定されていない場合（設定画面から曜日を全部消した場合）は、
  一覧の代わりに「設定してください」という案内を表示する

### 4.3 カレンダー

- 当月のごみ出し日を月表示のカレンダーで一覧する（日曜始まり）
- 前月・次月に移動できる。当月を表示していないときは「今月」ボタンで戻れる
- 各日のセルには区分の短縮名（最大3件、超過分は「+N」）を色付きで表示する
- 日をタップすると日別詳細シートを開く
- 凡例として5区分のバッジを表示する

### 4.4 設定

- 現在の地区（区・地区名）を表示し、タップで設定変更画面（初回設定と同じUIを流用）を開ける
- 区分ごとの設定中の収集曜日を一覧表示する（未設定なら「未設定」）
- 早朝収集地区に設定している場合はその旨を表示する
- 区分ごとの出し方（代表品目・出し方の要点）を折りたたみ表示する
- アプリについての注記（分別区分・出し方は市の案内の要約であり全文でないこと、出典URL）を表示する

### 4.5 日別詳細（共通ボトムシート）

- ホーム・カレンダーの両方から、日付をタップすると同じボトムシートを開く
- その日の日付・区分・出し方の要点を表示する

## 5. データ仕様

### 5.1 収集区分（5種固定）

もえるごみ／もえないごみ／有害危険ごみ／資源物1類／資源物2類。各区分は
`id`・正式名称・短縮名（カレンダーのセル用）・代表品目・出し方の要点を持つ。
表示順はこの宣言順で固定。

### 5.2 収集ルール

さいたま市の収集日はすべて「◯曜日」を軸に決まっており、日付そのもの（毎月15日など）で
決まる区分は存在しない。そのため収集ルールは以下の2要素だけで全パターンを表現する。

- 曜日（月〜日）
- 月内の週番号の集合。`null`なら毎週。週番号は「その月で何回目のその曜日か」で、
  カレンダーの行位置とは無関係（月初が日曜でも第1木曜はその月最初の木曜になる）

1つの区分が複数のルールを持てる（もえるごみが週2回など）。

### 5.3 収集休止日

1月1日〜3日のみ。さいたま市は祝日も収集するため、祝日カレンダーは持たない。

### 5.4 地区データ

同梱アセット（`assets/data/areas.json`）に以下を持つ。

- `presets`：曜日入力の出発点となる雛形。もえるごみの曜日だけが決まっている
- `areas`：町丁目から確定できる地区データ。**現時点では空**。市の地区表（収集日カレンダー）を
  取り込めるようになった時点でここを埋める設計になっている（`AreaCatalog.areasInWard()`は実装済み）
- `disclaimer`：データの確からしさについての但し書き
- `source`：出典URL

### 5.5 設定の永続化

ユーザーが確定した地区（区・地区名・区分ごとのルール一覧・早朝収集地区フラグ）を
端末内のキーバリューストアにJSONでまるごと保存する。個人を特定する情報は含まない。
保存済みデータが壊れている場合は初回設定に戻す（クラッシュさせない）。

## 6. 非機能要件

- **通信しない**：収集ルールの判定・設定の保存は端末内で完結する
- **縦画面固定**：カレンダーも一覧も縦に読む前提のレイアウト
- **色だけに依存しない**：区分は色・アイコン・短縮名の三重符号化で区別する。
  カレンダーのセルのように狭い場所でも短い名称を必ず添える
- **日本語UI固定**：多言語対応は行わない
- テスト：日付計算・データ読み込みなどのロジックはFlutter非依存の単体テストで担保し、
  画面はウィジェットテストで基本動作を担保する（詳細は[design.md](design.md)を参照）

## 7. スコープ外（現時点では持たない）

- 町丁目から地区を自動で引く機能（地区表データが空のため。[next-phase.md](next-phase.md)で扱う）
- ごみ出し前夜などのローカル通知（[next-phase.md](next-phase.md)で扱う）
- 粗大ごみの受付可否判定・「これは出せるか」をAIに聞く機能（ファーストリリース対象外）
- サーバー通信・アカウント機能・複数地区の同時管理
