# AI分別相談の精度検証（issue #41）

サーバーも広告も作る前に、機能として成立するかを測るためのもの。

## 何を測っているか

案Bの設計を前提にしている。**AIの役割は「利用者の言い方を辞書の品目に
対応づけること」だけ**で、区分（もえるごみ等）は辞書の記載をそのまま出す。
この設計なら、表示される区分は必ず市の資料に由来するので、
AIが間違った区分を答える余地が構造的に無い。

だから測るべきは次の2点だけになる。

1. 利用者の言い方を、正しい品目に対応づけられるか
2. 辞書に無いものを、無いと言えるか（ここが甘いと機能として出せない）

## 使い方

```bash
python3 scripts/ai_eval/run_eval.py            # 全50件
python3 scripts/ai_eval/run_eval.py --limit 5  # 抜き取り
```

手元の `claude` CLIに投げるだけなので、サーバーもAPIキーも要らない。

- `cases.json` … 検証データ。`expected` は辞書に実在する品目名か、
  該当なしを表す `null`。判断が割れる問いは `accept_also` に別解を書く
- `run_eval.py` … 候補の絞り込み＋問い合わせ＋答え合わせ
- `result.json` … 実行結果（`--out` で変えられる）

## 検証データを直すときの注意

**正解を書くのは思ったより難しい。** 実際、最初に用意した50件のうち
5件は正解の方が間違っていた（AIの答えが正しかった）。

- 「プラスチックの弁当箱」→「食品トレイ」と書いていたが、
  辞書には「弁当の容器（プラスチック製）」があった
- 「使用済みの注射針」「土」「犬のフン」を辞書に無いと決めつけていたが、
  「注射針」「土」「ペットのふん」がいずれも実在した

`expected` を書いたら、必ず `assets/data/dictionary.json` に
その名前が実在するか確かめること（run_eval.pyは実在チェックをしない）。

## 分かっていること

正答率そのものより、**外した理由の内訳**を見た方がよい。

候補に正解が入っていなければAIは絶対に当てられないので、
絞り込みの取りこぼしがそのまま上限になる。逆にそこさえ通れば、
AIはほぼ正しく選べている。

残っている取りこぼしは、いずれも**品目名と入力で文字が重ならない**もの。

| 入力 | 正解 | なぜ拾えないか |
|---|---|---|
| けいたいでんわ | 携帯電話・ＰＨＳ | 読みが同じでも文字が違う |
| けいこうとう | 蛍光管・蛍光ランプ | 同上 |
| こわれた傘 | かさ | 漢字とひらがなの違い |
| 飲み物を飲むときの細い管 | ストロー | 説明文であって品目名でない |
| electric fan | 扇風機 | 外国語 |

**辞書に読みがなを持たせれば、上4件は拾える見込みがある。**
市の早見表はかな行（`kanaHead`）しか持っていないので、
読みがな自体を別途用意する必要がある。
